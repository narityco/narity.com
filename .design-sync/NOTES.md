# design-sync notes — narity.com

## What this repo is, for sync purposes

narity.com is a hand-written **static HTML/CSS site**. There is no
`package.json` at the repo root, no build, no bundler, no React, no Storybook.
The design system is therefore synced in the converter's **tokens-only** mode:
zero components, `styles.css` + tokens + guidelines only, with a deliberately
empty `_ds_bundle.js`.

**The empty bundle and `components: 0` are correct output, not a failed build.**
`[ZERO_MATCH] no component exports — treating as tokens-only DS` is the line
that confirms the mode engaged (`lib/source-kit.mjs`); `package-validate.mjs`
prints `tokens-only DS — no component previews` and exits 0.

## The synthetic package

The converter needs *a package* to point at. `.design-sync/brand/` is that
package and nothing else — it is a sync input, never shipped to the website:

- `package.json` — `narity-brand@1.0.0`, entry `./index.js`
- `index.js` — `export {}`. Its emptiness is what selects tokens-only mode.
- `tokens/tokens.css` — the eight `:root` custom properties
- `tokens/fonts.css` — the Inter `@import` from the font host
- `brand.md`, `patterns.md` — copied into `guidelines/` by `guidelinesGlob`
- `styles.css` — **generated by `prep.sh`, gitignored, never hand-edit**

## Run it

```sh
sh .design-sync/prep.sh
node .ds-sync/package-build.mjs --config .design-sync/config.json \
  --node-modules ./.ds-sync/node_modules --entry ./.design-sync/brand/index.js --out ./ds-bundle
node .ds-sync/package-validate.mjs ./ds-bundle --no-render-check
```

`prep.sh` is **not optional** — it exists because of two converter bounds that
cost a build cycle each to discover:

- `cfg.cssEntry` is bounded to the package dir **and realpath'd**, so it can
  neither be `../../assets/style.css` nor a symlink to it (`! cssEntry: …
  resolves outside the package — skipped`, and then a misleading
  `[CSS_RUNTIME] no static CSS found`). prep copies the file in instead.
  `assets/style.css` stays the single source of truth.
- `cfg.tokensGlob` is only honoured **under `node_modules/<tokensPkg>`**
  (`lib/css.mjs: copyTokens` returns immediately when `tokensPkg` is unset).
  Hence `tokensPkg: "narity-brand"` plus the symlink prep creates. Because
  `.ds-sync/node_modules` is regenerated per clone, so is the symlink.

`guidelinesGlob` dest **preserves the package-relative subpath**, so a glob of
`guidelines/*.md` emits `guidelines/guidelines/*.md`. The `.md` files therefore
live at the package root with a glob of `*.md`. If you add a `README.md` to
`.design-sync/brand/`, it will be swept into the upload — name new files
deliberately.

## Known warns (expected — not new)

- `[FONT_REMOTE] "Inter"` — Inter is loaded from the font host via
  `tokens/fonts.css`, exactly as `index.html` loads it. No fonts are shipped
  and none should be.
- `[RENDER_SKIPPED]` — accepted deliberately, with the user's sign-off. There
  are **zero** `<Name>.html` previews in a tokens-only build, so the render
  check has nothing to open; installing playwright (~200MB) would only change
  the exit code. Verified instead by opening `.design-sync/preview-page.html`
  in a real browser (see below).
- `[DTS_REACT] @types/react not found` — resolves against the *package* dir,
  not `.ds-sync/node_modules`. Harmless: with zero components nothing is typed.
- `[CSS_RUNTIME]` — only if `cssEntry` fails to resolve. If you see it, prep
  didn't run.

## Visual verification

`.design-sync/preview-page.html` links **only** `../ds-bundle/styles.css` — the
exact transitive closure a rendered design receives. Serve the repo root
(`node .ds-sync/storybook/http-serve.mjs .`) and open
`/.design-sync/preview-page.html`. It exercises header, hero, card grid, stats,
checklist, product row, form, and footer. If that page looks like narity.com,
the upload is right. This is the substantive check for this repo — not the
render check.

## Re-sync risks

- **`assets/style.css` drift is the main one.** `prep.sh` re-copies it every
  run, so the bundle can't go stale — but `.design-sync/brand/tokens/tokens.css`
  is a **hand-maintained mirror** of the `:root` block. If someone adds or
  renames a token in `assets/style.css`, tokens.css will not follow, and
  `package-validate.mjs` will report the mismatch as `tokens: N defined,
  M referenced`. Diff the two whenever that count moves.
- **`.design-sync/conventions.md` names ~51 classes and 8 tokens verbatim.**
  A rename in `assets/style.css` silently makes the design agent emit
  vocabulary that no longer resolves — unstyled output, nothing to catch it.
  Re-run the validation pass on every sync:
  ```sh
  rg -o '`\.[a-zA-Z][a-zA-Z0-9_.-]*`' .design-sync/conventions.md .design-sync/brand/*.md \
    | sed 's/.*`\.//; s/`$//' | tr '.' '\n' | sort -u \
    | while read c; do [ -n "$c" ] && (rg -q "\.$c\b" ds-bundle/_ds_bundle.css || echo "MISSING: .$c"); done
  ```
- **The logo SVGs are inlined into `guidelines/brand.md`**, because
  `guidelinesGlob` copies `.md` only and nothing else carries binaries into the
  upload. They are copies: if `assets/*.svg` changes, brand.md does not.
- **The generated README body is wrong for this DS** — it describes a React
  library, "0 components", and a `window.NarityBrand.*` import flow that does
  not exist. `conventions.md` is prepended above it and opens by contradicting
  it explicitly. If the converter's README template changes, re-read the
  stitched result and make sure the correction still lands first.
- **`section { min-height: 100vh }` ships globally** in `assets/style.css`. It
  is right for the marketing site and wrong for app screens; conventions.md
  calls it out as gotcha #1. Don't "fix" it in the site CSS on the design
  system's behalf — that's a website decision.
- Nothing under `assets/` or `*.html` is modified by this sync, by design.
